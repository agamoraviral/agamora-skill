# Вывод: PDF и редактируемый PPTX из одного HTML

## Порядок

```bash
python build_<тема>.py                                   # генератор дека → deck.html (шрифты и логотип внутри)
python <скилл>/scripts/render_pdf.py deck.html            # → deck.pdf, проверка числа страниц
python <скилл>/scripts/export_pptx.py deck.html           # → deck.pptx, редактируемый
python <скилл>/scripts/qa.py deck.html --pdf deck.pdf     # → ошибки, предупреждения, листы кадров
```

Нужны: Python 3.9+, `python-pptx`, `pymupdf`, `Pillow`, `lxml` (ставится с python-pptx) и Chrome,
Chromium или Edge. Путь к браузеру находится сам (Windows, macOS, Linux); иначе — переменная `CHROME_PATH`.
Сеть не нужна.

## PDF

Headless Chrome `--print-to-pdf`, размер страницы — из `@page{size:1600px 900px}`. Не puppeteer и не
сторонние библиотеки: так PDF совпадает с тем, что видно в браузере. `render_pdf.py` сверяет число страниц с
числом слайдов: расхождение значит, что содержимое вылезло за 900 px.

Выученные на практике тонкости:
- путь в `--print-to-pdf` только абсолютный — иначе Chrome падает с «Access is denied»;
- нужен `--virtual-time-budget`, чтобы шрифты и сценарии успели отработать до печати;
- Chrome иногда молча не перезаписывает PDF — скрипт удаляет старый файл и проверяет, что новый появился;
- каждый запуск идёт со своим временным профилем, иначе второй Chrome отдаёт работу первому и выходит
  с пустым результатом;
- страница PDF у Chrome задана в пунктах: 1600 px = 1200 pt; при растеризации множитель 1600 / 1200.

## PPTX

`export_pptx.py` вставляет в копию дека `deck_export.js` и просит Chrome разложить каждый слайд:

| Что в HTML | Что в PPTX |
|---|---|
| блок с фоном, рамкой, скруглением | прямоугольник / скруглённый / овал, заливка с прозрачностью, линия, пунктир |
| линейный градиент фона | градиентная заливка |
| SVG `rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, `path` | родные фигуры и кривые (дуги → кубические кривые), стрелки на концах линий |
| текст (HTML и SVG) | редактируемая текстовая рамка: шрифт, кегль, насыщенность, цвет, разрядка, прописные, выравнивание, точный межстрочный; переносы строк — как в PDF |
| `img` | картинка с обрезкой по `object-fit` |
| фильтры, маски, сложные тени, текст по кривой | «растровый остров»: картинка на своём месте и в своём порядке наложения |
| `<aside class="notes">` в слайде | заметки докладчика |

Единицы: слайд 13,333 × 7,5 дюйма, 1 px = 7 620 EMU = 0,6 pt.

**Шрифты в PPTX.** В PPTX записываются имена начертаний: «IBM Plex Sans», «IBM Plex Sans Medm»,
«IBM Plex Sans SmBld», «Onest», «Onest Medium», «Onest SemiBold», «Unbounded Medium», «Unbounded SemiBold»,
«Unbounded», «Caveat». Чтобы файл выглядел так же, как PDF, шрифты из `assets/fonts/` должны быть
установлены у того, кто открывает PPTX. Если у получателя их нет и установить нельзя:

```bash
python export_pptx.py deck.html --font "IBM Plex Sans=Segoe UI" --font "Caveat=Segoe Print"
```

Segoe UI метрически близка к IBM Plex Sans (±2,5 %), вёрстка не разваливается. Экспортёр меряет каждую
строку метриками итогового шрифта и при нехватке ширины ужимает кегль блока до 8 %, о большем —
предупреждает.

**Переносы.** По умолчанию строки разбиты так же, как в PDF (разрывы внутри одного абзаца). Если PPTX будут
активно править, `--reflow` отдаёт переносы PowerPoint.

**Ограничения.** PowerPoint кладёт базовую линию при точном межстрочном интервале немного иначе, чем
браузер: возможен сдвиг текста по вертикали на 1–3 px. Растровые острова не редактируются как фигуры —
чтобы их было меньше, не используйте в деке фильтры, маски и тени (они и так против правил оформления).
Растеризовать PPTX на машине без PowerPoint нельзя; геометрию проверяет сравнение рамок PPTX с кадрами
PDF, а переполнение — метрики шрифта.

## Доставка

- Имена: «<Тема> — <вид> vN.M.pdf / .pptx».
- Файлы — туда, куда просил автор; не публиковать как веб-страницу без прямой просьбы.
- При копировании на сетевой диск: сначала под временным именем, затем замена; сверить размер.
