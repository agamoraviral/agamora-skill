# agamora-presentations — презентации для руководства и аналитики

Скилл делает деки, которые выглядят как работа дизайнера аналитических презентаций: одна мысль на слайд,
крупная графика вместо текста, строгая типографика, фирменная палитра. Дек собирается в HTML из
компонентов `deckkit`, затем выводится в **PDF** (печать Chrome) и **редактируемый PPTX** (та же
геометрия, родной текст и фигуры) и проходит автоматическую и визуальную проверку.

Все правила выросли из реальных замечаний руководства: почему каждое из них существует — в
`references/lessons.md`.

## Жёсткие правила (нарушение — дек возвращают)

1. **Один слайд — одна мысль, и слайд читается сам:** метка раздела → короткий заголовок-тезис
   (2–6 слов: «Вес решения решает») или вывод с числом («Переход окупается за 1,3 года»), при
   необходимости — лид-строка с полной мыслью → **один акцент** (главное число, лидирующая полоса, порог,
   тёмная карточка «наш вывод») → доказательства тихим тоном → вывод одной фразой внизу. Не тема
   («Экономический эффект»). Приёмы — `references/design.md`, раздел 0, и модуль `deckkit.accents`.
2. **Главный объект на каждом слайде** — схема, график, дорожная карта или одно крупное число; текст —
   подписи к нему. Не больше 3–4 текстовых блоков и 4 чисел. Где проще текстом — крупным текстом на
   шкале, но не таблицей. Таблицы — только в приложении.
3. **Кегль в теле — от 20 px**, главные числа — 88–120 px. Никаких подвалов, сносок, «*», слайда
   «Источники»: оговорка — в подпись крупно, формулы — в приложение «Как посчитан эффект».
4. **Без признаков вайбкодинга:** иконок в цветных квадратах, таблеток-меток, кружков с галочками,
   тонированных скруглённых карточек, градиентов, теней, текстур, эмодзи, восклицательных знаков, лозунгов.
5. **И без обратного перекоса:** не «одни таблицы», не сплошной текст, не пустые полосы. Слайд наполнен
   крупным объектом, внутри — воздух.
6. **Живой деловой язык:** глаголы вместо цепочек существительных, без калек и англицизмов, без пар
   «X — Y»; прочитать вслух. Незнакомый термин — объяснить при первом упоминании.
7. **Честные числа:** только подтверждённые, консервативная оценка, одна единица и один горизонт,
   крупный итог разложен на проверяемые статьи. Не хватает данных — сказать автору, не додумывать.
8. **Фирменная графика вместо картинок:** плоскости основного цвета и мотив бренда. Пейзажи, сток,
   «детские» схемы-звёзды — нет. Строгие линейные иконки — только там, где обозначают участника или смысл.
9. **Рукописная пометка** (Caveat) у ключевой цифры — разрешённый человеческий акцент: одна на слайд,
   до 5 слов, не больше чем на ~40 % слайдов.
10. **На выходе — PDF и PPTX из одного HTML.** Для руководства — две версии (короткая 1–4 слайда и
    подробная) из одного генератора; правка вносится в обе.

Полный свод с причинами — `references/rules.md`; исполнение уровня дизайнера (сетка, шкала кеглей,
контраст, графики, Гант, обложка) — `references/design.md`.

## Процесс

### 1. Бриф
Выяснить (из запроса, файлов, истории — спрашивать только недостающее): адресат и решение, которого ждём;
тип материала (стратегический дек, эффект для защиты, детализация инициативы, форма компании, короткая
версия); источники чисел; бренд; срок и формат сдачи. Если есть согласованный образец того же типа —
строить по нему.

### 2. Сюжет
План дека — по строке на слайд: заголовок-вывод + главный объект + какие данные его несут. Стратегический
дек: боль и её стоимость → что меняется → где мы → план (Гант) → эффект → решения. Короткая версия:
(1) боль и эффект, (2) план на год Гантом, (3) эффект одним числом и три решения. Показать план автору,
если дек большой или тема новая.

### 3. Форма подачи
Для каждого слайда выбрать форму по смыслу данных — таблица «Форма визуализации под смысл» в
`references/rules.md` (раздел 8) — и компонент из `references/components.md`. Как выглядит каждый
компонент — галерея: `python <скилл>/examples/gallery.py` → `examples/out/gallery.pdf`.

### 4. Сборка
Генератор `build_<тема>.py` рядом с материалами (не в папке скилла). Числа — константами вверху: один
источник для обеих версий, PDF и PPTX.

```python
import os, sys
SKILL = r"<путь к папке скилла>"                 # в плагине: ${CLAUDE_SKILL_DIR}
sys.path.insert(0, os.path.join(SKILL, "scripts"))
from deckkit.tokens import page, build, mn, bn, NAVY, BLUE, LBLUE, MUTED, RULE
from deckkit.primitives import big, hand
from deckkit.canvas import Canvas, chain
from deckkit import accents as A, charts as C, schemes as S, layouts as L
from deckkit.gantt import gantt
from deckkit.cover_iso import cover_slide
from deckkit.cover_flow import swarm_to_bank

EFFECT = [310, 420, 560, 700, 820]                # млн ₽ по годам — единственный источник чисел
YEARS = ["2027", "2028", "2029", "2030", "2031"]

F = [cover_slide("Название<br>в две строки", "Метка · дата", "Зачем и как", "Для кого · дата", swarm_to_bank())]
F.append(page("Задача", "Цель и рамки",
              A.hero_number("−30", "%", "затрат на сопровождение за три года", rows=[("Периметр", "120 систем"),
                            ("Срок", "2027–2029"), ("Бюджет", "310 млн ₽ поэтапно")]),
              lead="Короткий тезис в заголовке, полная мысль — в лид-строке"))
F.append(page("Эффект", f"За пять лет подход даёт {bn(sum(EFFECT))} млрд ₽",
              C.vbars(EFFECT, YEARS, 1456, 560, hi=4), notes="Что сказать на этом слайде"))
# … остальные слайды по плану

if __name__ == "__main__":
    n = build(F, "Название дека", "deck.html")     # brand="<имя>" или переменная DECK_BRAND
    print(n, "слайдов")
```

Холсты и графики считают от ширины тела 1456 px; высоту холста подбирать под тело слайда (≈560–660 px),
а не растягивать ряды. Свою графику — через `Canvas` (блоки HTML + связи SVG) и SVG-примитивы: они
переходят в PPTX родными фигурами. Фильтры, маски и тени в PPTX станут картинками — избегать.

### 5. Вывод и проверка

```bash
python <скилл>/scripts/render_pdf.py deck.html
python <скилл>/scripts/export_pptx.py deck.html [--font "IBM Plex Sans=Segoe UI"]
python <скилл>/scripts/qa.py deck.html --pdf deck.pdf
```

`qa.py` должен пройти без ошибок. Затем — **обязательно посмотреть все листы кадров** (`sheet-N.png`) по
чек-листу `references/qa.md`, прочитать каждый слайд вслух, сверить числа между слайдами, версиями и
форматами. Править генератор → пересобрать → проверить снова.

### 6. Сдача
Имена «<Тема> — <вид> vN.M.pdf / .pptx». Отчёт автору коротко: что сделано, какие допущения и спорные места
проверить, чего не хватило в данных, где файлы. Снимки экранов и внутренние материалы в переписку не
выводить. Не публиковать дек как веб-страницу без прямой просьбы.

## Бренд
Палитра по умолчанию нейтральная, без логотипа. Фирменный стиль — `brand.json` (цвета, шрифты, логотип,
дополнительный CSS) в `brands-local/<имя>/` (не попадает в git) или `brands/<имя>/`; подключение —
`build(..., brand="<имя>")` или переменная `DECK_BRAND`. Готовый профиль в духе режима Design —
`brand="editorial"` (тёплый фон, заголовки Unbounded, текст Onest, один горячий акцент). Формат —
`references/brand.md`.

## Структура скилла

| Путь | Что там |
|---|---|
| `references/rules.md` | свод правил подачи, языка, чисел, композиции, цвета, форм визуализации — с причинами |
| `references/design.md` | исполнение уровня дизайнера: сетка, шкала кеглей, цвет и контраст, графики, Гант, обложка, нормы |
| `references/components.md` | справочник компонентов `deckkit` (собирается из кода) |
| `references/qa.md` | проверка перед сдачей: автоматическая, глазами, чтение, сверка |
| `references/export.md` | PDF и PPTX: как устроено, шрифты, ограничения, тонкости Chrome |
| `references/brand.md` | формат бренда, роли палитры, мотив |
| `references/lessons.md` | журнал опыта: что отвергали и принимали и почему |
| `scripts/deckkit/` | библиотека компонентов: каркас, приёмы акцентов, холст схем, графики, схемы, Гант, обложки, иконки |
| `scripts/render_pdf.py`, `export_pptx.py`, `qa.py` | вывод и проверка |
| `examples/gallery.py` | галерея всех компонентов на вымышленных данных |
| `assets/fonts/` | IBM Plex Sans, Onest, Unbounded, Caveat (лицензия SIL OFL 1.1) |
| `brands/` | профили: `example`, `editorial`; свои — в `brands-local/` |
